# HumanitZ — автодеплой в Timeweb Cloud App Platform

Комплект для автоматической сборки, установки и запуска HumanitZ через
**Docker Compose**. SSH, команды сборки и запуска не нужны.
Реальный деплой и подключение игроков ещё не проверены.

## Файлы репозитория

```text
docker-compose.yml
README.md
humanitz/
  Dockerfile
  LICENSE.md
```

Загрузите содержимое всего проекта в Git-репозиторий: `docker-compose.yml`
должен находиться непосредственно в корне. Путь к Dockerfile указан в Compose.

## Настройка в панели Timeweb

1. В App Platform создайте приложение типа **Docker → Docker Compose**.
2. Подключите репозиторий через интеграцию GitHub, GitLab или Bitbucket.
3. Выберите ветку и включите сборку по последнему коммиту для автодеплоя.
4. Выберите конфигурацию x86_64 с ресурсами для игрового сервера.
5. Запустите деплой. Дополнительные команды и обязательные переменные не нужны.

Timeweb соберёт образ. При запуске LinuxGSM автоматически скачает HumanitZ
через SteamCMD и запустит сервер. Первый запуск требует времени на загрузку
игры; следите за логами приложения. Успешный деплой сам по себе не подтверждает
готовность игрового сервера. Проверке контейнера дано 30 минут на установку.

## Подключение игроков

В Compose опубликованы UDP **7777** (игра) и **27015** (Steam Query).
Для подключения используйте публичный IP приложения из дашборда и порт 7777.
HTTP-домен приложения не является веб-интерфейсом игрового сервера.

Документация разрешает дополнительные хост-порты, но явно не подтверждает
доступность входящего UDP. Проверьте подключение из игры или уточните у
поддержки Timeweb доступность UDP 7777 и 27015 для Docker Compose.
Dockerfile не может обойти сетевые ограничения платформы.

## Сохранения при автодеплое

App Platform запрещает `volumes` в Compose; файлы контейнера теряются при
новом деплое. Поэтому постоянный том из прежней конфигурации исключён.
Существующие данные этим изменением не удаляются.

**Этот комплект не обеспечивает сохранение мира между деплоями.**
Новый контейнер может заново установить игру и создать новый мир.
Для постоянного мира требуется интеграция с внешним хранилищем: восстановление
перед запуском и автоматическое резервное копирование сохранений. Она пока
не настроена: хранилище и доступ к нему не заданы.

## Проверка и источники

Проверены пути файлов и отсутствие запрещённых параметров `name`, `volumes`
и сети `host`. Dockerfile сохраняет штатную автоматическую установку LinuxGSM.
Сборка и запуск не проверены: локально Docker отсутствует, доступа к App Platform нет.
