# HumanitZ — автодеплой в Timeweb Cloud App Platform

Комплект для автоматической сборки, установки и запуска HumanitZ через
**Docker Compose**. SSH, команды сборки и запуска не нужны.
Реальный деплой и подключение игроков ещё не проверены.

## Файлы репозитория

```text
docker-compose.yml
README.md
humanitz/
  Dockerfile
  configure-humanitz.sh
  LICENSE.md
```

Загрузите содержимое всего проекта в Git-репозиторий: `docker-compose.yml`
должен находиться непосредственно в корне. Путь к Dockerfile указан в Compose.

## Настройка в панели Timeweb

1. В App Platform создайте приложение типа **Docker → Docker Compose**.
2. Подключите репозиторий через интеграцию GitHub, GitLab или Bitbucket.
3. Выберите ветку и включите сборку по последнему коммиту для автодеплоя.
4. Выберите конфигурацию x86_64 с ресурсами для игрового сервера.
5. В переменных приложения задайте **ADMIN_PASSWORD**: ваш пароль администратора
   из 16–128 латинских букв, цифр, дефисов или подчёркиваний. Без него деплой
   остановится с понятной ошибкой. Пароль не нужно записывать в репозиторий.
6. Запустите деплой. Команды сборки и запуска вручную не нужны.

Timeweb соберёт образ. При запуске LinuxGSM автоматически скачает HumanitZ
через SteamCMD и запустит сервер. Первый запуск требует времени на загрузку
игры; следите за логами приложения. Успешный деплой сам по себе не подтверждает
готовность игрового сервера. Проверке контейнера дано 30 минут на установку.

## Подключение игроков

В Compose опубликованы UDP **7777** (игра) и **27015** (Steam Query).
Для подключения используйте публичный IP приложения из дашборда и порт 7777.
HTTP-домен приложения не является веб-интерфейсом игрового сервера.

### Первое подключение

1. Откройте приложение в Timeweb и дождитесь окончания установки игры и запуска
   сервера в логах. Одного статуса «Деплой выполнен» недостаточно.
2. На вкладке «Дашборд» скопируйте публичный IPv4 приложения.
3. Запустите актуальную версию HumanitZ в Steam и откройте раздел сетевой игры
   со списком серверов.
4. Выберите подключение по IP (Direct Connect / Connect by IP; название зависит
   от версии и языка игры). Укажите IP приложения и игровой порт `7777`.
   Если поле одно, используйте формат `IP:7777`, без `http://` и `https://`.
5. Подключитесь и введите пароль сервера, если он настроен. Передайте друзьям
   тот же адрес и пароль для входа.

Можно также найти сервер в игровом списке по имени. Проверьте фильтры выделенных
серверов и серверов с паролем. При нестандартном `SearchID` нужен соответствующий
идентификатор поиска. Имя приложения в Timeweb не меняет имя сервера в игре.

`27015` — порт запросов Steam, а `7777` — игровой порт; это разные назначения.
Для поля, которое явно запрашивает Query Port, укажите `27015`.

### Если не удаётся подключиться

- Проверьте, что установка завершилась, игровой процесс запущен, а в логах нет
  повторяющихся ошибок или перезапусков.
- Сверьте публичный IP в дашборде: после изменений инфраструктуры он может
  отличаться от адреса, который вы сохранили ранее.
- На вкладке «Сеть» проверьте подключённый Firewall. Если он ограничивает
  входящий трафик, разрешите UDP 7777 и UDP 27015.
- Проверьте обновления игры в Steam и сервера; несовпадение версий может мешать входу.
- Если сервер не виден в списке, попробуйте подключение по IP. Если и оно
  завершается тайм-аутом, проверьте доступность UDP у поддержки Timeweb.
- Ошибка в браузере при открытии технического домена не доказывает, что игровой
  сервер выключен: у HumanitZ здесь нет HTTP-страницы.

Документация разрешает дополнительные хост-порты, но явно не подтверждает
доступность входящего UDP. Проверьте подключение из игры или уточните у
поддержки Timeweb доступность UDP 7777 и 27015 для Docker Compose.
Dockerfile не может обойти сетевые ограничения платформы.

## Управление через App Platform

Откройте **App Platform → ваше приложение**. Основные действия доступны без SSH:

| Задача | Где выполнить |
| --- | --- |
| Проверить сборку и ошибки деплоя | Вкладка «Деплой», при необходимости расширенные логи |
| Проверить запуск игры | Логи приложения/контейнера, если этот раздел доступен для вашего Compose-приложения |
| Перезапустить сервер | Действие перезапуска контейнера/сервера в панели приложения |
| Временно выключить или включить | Приостановка приложения и последующий запуск в той же панели |
| Проверить CPU, память и диск | «Дашборд» |
| Увеличить ресурсы | «Настройки» → «Выбрать конфигурацию» |
| Отключить автодеплой | «Настройки» → «Настройки деплоя» → «Редактировать» → выключить сборку по последнему коммиту |
| Развернуть изменения | Отправить коммит в подключённую ветку при включённом автодеплое |

Перед перезапуском предупредите игроков: соединения будут прерваны.
Для обычного перезапуска используйте действие перезапуска в панели.
Повторный деплой пересоздаёт приложение и может потерять мир — см. раздел
о сохранениях ниже. Откат к старому коммиту откатывает код, но не восстанавливает мир.

### Обновление игры

Штатный процесс LinuxGSM проверяет обновления установленной игры при запуске
контейнера. Для обновления перезапустите приложение и дождитесь завершения
проверки в логах. Если контейнер новый, LinuxGSM заново скачает сервер.

### Имя, пароль и настройки игры

Настройки HumanitZ находятся **внутри контейнера**, в файле
`/data/serverfiles/HumanitZServer/GameServerSettings.ini`, созданном после установки.
В секции `[Host Settings]` используются:

| Параметр | Назначение |
| --- | --- |
| `ServerName` | Имя в списке игровых серверов |
| `Password` | Пароль входа для игроков |
| `AdminPass` | Отдельный пароль администратора |
| `SaveName` | Имя сохранения; изменение может переключить сервер на другой мир |
| `SearchID` | Группа поиска сервера; нестандартное значение влияет на его видимость |

Переменная Timeweb **ADMIN_PASSWORD** автоматически записывается в `AdminPass`
после установки/обновления файлов игры и перед её запуском. Значение не выводится
нашим скриптом в лог. При изменении пароля в панели примените настройки и
выполните новый деплой; учитывайте потерю мира без внешнего хранилища.

Отдельного игрового пользователя с логином `admin` нет. Администратор — ваш
обычный Steam-пользователь после ввода `/AdminAccess ВАШ_ПАРОЛЬ` в игровом чате.
Любой игрок, знающий этот пароль, может получить права администратора.
Это не пароль аккаунта Timeweb, SSH или входа игроков на сервер.

Для остальных настроек автоматического переноса переменных пока нет:
добавление `ServerName` или `Password` в панель само по себе INI-файл не меняет.

Если у вашего приложения доступна консоль контейнера, через неё можно
остановить игровой процесс, отредактировать существующий INI-файл и снова
запустить игру. Однако FAQ Timeweb явно обещает консоль только для backend
и Dockerfile; для выбранного режима Docker Compose её наличие не подтверждено.
Не рассчитывайте на SSH или файловый менеджер VPS.

Для изменения остальных игровых настроек полностью через интерфейс Timeweb
потребуется расширить обработку переменных при запуске. Правки только внутри
контейнера не переживают новый деплой.

### Администрирование из игры

После того как в конфигурации задан ваш `AdminPass`, подключитесь к серверу
и в игровом чате выполните `/AdminAccess ВАШ_ПАРОЛЬ`. Используйте значение
`AdminPass`, а не пароль входа `Password`.

| Команда в игровом чате | Действие |
| --- | --- |
| `/SaveGame` | Немедленно сохранить игру |
| `/adminw` | Открыть административный интерфейс игры |
| `/admintag` | Переключить отметку администратора в чате |

`/SaveGame` сохраняет мир в контейнере, но не делает внешнюю резервную копию
и не защищает от потери данных при новом деплое. Внешний RCON в этом комплекте
не настроен и его порт не опубликован.

## Сохранения при автодеплое

App Platform запрещает `volumes` в Compose; файлы контейнера теряются при
новом деплое. Поэтому постоянный том из прежней конфигурации исключён.
Существующие данные этим изменением не удаляются.

**Этот комплект не обеспечивает сохранение мира между деплоями.**
Новый контейнер может заново установить игру и создать новый мир.
Для постоянного мира требуется интеграция с внешним хранилищем: восстановление
перед запуском и автоматическое резервное копирование сохранений. Она пока
не настроена: хранилище и доступ к нему не заданы.

## Проверка и источники

В предоставленном логе от 22.09.2026 сборка началась в 22:05:42 и закончилась
в 22:10:34 строкой `Build succeeded`. Повторы `exporting to image` и `retrying`
были на этапе скачивания/отправки образа и не помешали завершению сборки.
В этом файле нет лога запуска контейнера или SteamCMD: по нему нельзя установить
причину ожидания после сборки. Для диагностики нужен лог контейнера и текущий
статус приложения из Timeweb. После применения настройки администратора ищите
сообщение `HumanitZ admin password configured from ADMIN_PASSWORD (value hidden).`
перед запуском игры; затем проверьте вход и `/AdminAccess` в самой игре.

Проверены пути файлов и отсутствие запрещённых параметров `name`, `volumes`
и сети `host`. Dockerfile сохраняет штатную автоматическую установку LinuxGSM.
Сборка и запуск не проверены: локально Docker отсутствует, доступа к App Platform нет.
